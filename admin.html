Improve property coordinates (from your StockNetwork export)

Most StockNetwork coordinates are rounded to about 1 km, so map pins can sit a kilometre out. Choose your StockNetwork resort export (the .csv you upload to the resort list) and this looks each property up by name on Google, then gives you two files: a review report (every property with a confidence rating and the suggested latitude/longitude), and a copy of your export with only the high-confidence coordinates swapped in, ready to load back into StockNetwork. It changes nothing in the hub itself. Each property looked up is one Google lookup.

StockNetwork location review

Every night StockNetwork's own API refreshes each property's Country, State, Area, District, City, City2 and Suburb in the hub. This compares them with the property's place in the location tree, which comes from its pin: Country, State = province, Area = Avante region, City and Suburb. Anything that differs, is blank on StockNetwork, or isn't placed yet is listed here. When StockNetwork sends a new coordinate, the hub also checks the property's name against Google and flags it here — "coordinate may be wrong" — if the name doesn't look like it belongs near that point. To fix a row, accept the suggested coordinate (or use Fix coordinates on the Master map), or queue a District, City2 or State correction for StockNetwork's team. "Corrected StockNetwork file" below then writes Country, State, Area, City, Suburb and District from the tree for every property. Nothing changes until you save.

StockNetwork cleanup wizard

One guided pass so that, once you load the file it builds into StockNetwork, StockNetwork and the hub agree on Country, Area, City, Suburb and Latitude/Longitude. One step at a time — nothing runs until you press that step's button.

Step 1 — Upload your StockNetwork export

Choose the StockNetwork Resort Information export (.csv). Nothing is looked up or changed yet — this only counts what needs doing and what it will cost.

Which properties to do

Estimated Google lookups for this choice

Step 2 — Find coordinates

Looks each property up on Google by its name and town — the same lookup “Improve property coordinates” uses — and sorts the answers into Confident (Google matched the property itself, within 15 km of the current pin), Unsure (matched by name, but far from the current pin or there was no pin to compare) and Not found (Google only found the town, or nothing). Nothing is saved to the hub in this step.

Step 3 — Place in the hub

Saves each property's coordinate in the hub (Google's where you accepted it, otherwise the best one already on file) and places it straight away in the location tree (Country > Province > Region > City > Suburb), the same way “Find & fix missing coordinates” does. Where the hub's coordinate now differs from StockNetwork's, the property is marked waiting for StockNetwork: until StockNetwork sends the same coordinate, the nightly sync, a resort-list CSV re-upload and the “Corrected StockNetwork file” tool all keep the hub's coordinate instead of going back to StockNetwork's old one. The mark clears itself once StockNetwork matches.

Step 5 — Build the file for StockNetwork

Builds one file in exactly the same format as your export — same columns, order, quoting, line endings and text encoding — with the new Latitude/Longitude and the hub's Country, City, Suburb (and Area, if you chose that). District, City2 and State are never changed, nor is any other column. Where the hub's town is an agricultural holding (e.g. “Renosterkop AH”), City becomes the nearest proper town within 40 km and the AH name goes in Suburb. You also get a change report listing every single change.

    2. Wait for the hub's next nightly StockNetwork sync (02:00 UTC — 04:00 South African time).

    How Payouts Work

    Where the numbers come from, and how to get each affiliate paid

    1

    Add the affiliate here first

    On the Affiliates tab, add each affiliate with their exact Hub affiliate ID (the same ID that's in their personal Hub link and their flight/booking links) and set what they earn for each channel — Accommodation, Flights, Activities, Car Hire, and Packages. These match the tabs in their own Hub. For each channel choose either a % of the revenue you log, or a fixed R flat amount paid every time you log an entry for that channel — whichever suits how you pay that affiliate.

    2

    Pull flight booking numbers from Impact.com

    Log into app.impact.com, then in the top navigation go to Reports → More Reports → Performance by Sub ID and Shared ID (or Reports → Advanced Action Listing for a booking-by-booking view). Every affiliate's flight bookings are tagged with their Hub affiliate ID as the Sub ID, since the Hub's "Your Flight Link" appends it automatically. Filter or group by Sub ID to see each affiliate's revenue for the period.

    3

    Pull accommodation numbers from StockNetwork

    Accommodation bookings run through each affiliate's own personal StockNetwork booking link rather than through Impact.com, so check StockNetwork's own reporting for booking revenue per affiliate over the same period.

    4

    Log the revenue on the Payouts tab

    Select the affiliate, choose which channel the revenue came from (Accommodation, Flights, Activities, Car Hire, or Packages), enter a period label (e.g. "August 2026") and the total revenue for that period, then click Add Revenue Entry. The amount you owe them is calculated automatically using that channel's own revenue share percentage.

    5

    Pay them, then mark it paid

    Once you've paid an affiliate (EFT, etc.), find that entry in their Payouts table and click Mark Paid. This updates their outstanding balance so you always know who's still owed money at a glance.

    💡 If you enter more than one revenue entry for the same period by mistake, just delete the wrong one from the entries table — deleting an entry automatically reverses its effect on that affiliate's totals.
